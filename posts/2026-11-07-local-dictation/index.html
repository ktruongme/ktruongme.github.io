The problem

Working with AI tools means a lot of typing: in chat apps, coding assistants, the browser and the terminal. For long prompts, speaking is faster than typing. But the existing dictation options each have a problem.

Dictation inside AI apps only works in that app. The dictation in Claude and ChatGPT is very good, but it only works inside those apps, and not always there either. For example, it doesn’t work in the Claude Code extension for VS Code when VS Code is connected to a remote machine over SSH. The GitHub Copilot app also has its own dictation, but it uses a fixed model that you can’t change: NVIDIA’s nemotron-speech-streaming-en-0.6b, a small English-only model that runs on your own computer.

Dictation that works everywhere is weaker. Windows voice typing (Win + H) works in every app, but it makes many more mistakes than the dictation in the AI apps. It sends your audio to Microsoft’s cloud speech service, and Microsoft doesn’t say which model it uses.

The goal is one dictation tool for the whole computer that types into whatever window is active. It should also be free, with no subscription and no word limit.

Such a tool has two parts: the app handles the shortcut key, records your voice and pastes the text, and the model turns the speech into text.

Handy: free, offline, open source

Handy is a free, open-source app (MIT license) for Windows, macOS and Linux. You hold a shortcut key, speak, and release it. Handy then pastes the text where the cursor is. Everything runs on your own computer, and you choose the model. Pick a shortcut key that other apps don’t already use, for example Caps Lock.

The best-known dictation app, Wispr Flow, runs in the cloud and is not fully free. Its results often feel better than the models in Handy because it also cleans up the text with AI, but the free plan allows only about 2,000 words a week (after that it slows down, with a hard limit at 5,000 words).2 Since both apps work the same way, one option is to use Wispr Flow until the limit, then switch to Handy.

Does Handy really use the GPU?

The test machine is a laptop with two GPUs: a built-in Intel GPU and an NVIDIA RTX PRO 500 (6 GB memory, 40 W). handy.exe shows up in nvidia-smi, but that only means the app draws its window on the GPU. To check if the model itself runs on the GPU, measure the GPU once per second while dictating:

1..75 | % { nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv,noheader; Start-Sleep 1 }

The results show a clear pattern:

  • While speaking: the GPU is at 0% and uses 0 MiB of memory. Handy only records.
  • After releasing the key: the GPU works at 91% for about 1 second, and memory goes from 0 to about 1 GB. This is the model loading and transcribing.
  • A little later: the memory is free again, because Handy unloads the model when it isn’t in use.

Good to know about speed and memory:

  • “Speed” is the waiting time after you stop talking. Whisper-type models transcribe the whole recording in one go. On this GPU the wait is about one second, which feels instant.
  • Model size decides the memory use, not the length of the recording. Speaking longer takes more time, not more memory.
  • Bigger models fit in memory, but they are slower. Handy rates Mistral’s Voxtral Mini 3B better for English. It is about three times bigger, so each phrase could take around 3–4 seconds on this GPU. This is an estimate and hasn’t been measured yet.

Recommended setup

Handy with Whisper large-v3-turbo on an NVIDIA GPU: free, offline, no word limit, about one second per phrase, and it works in every app. The text is less polished than Wispr Flow’s, but for prompts to an AI it is good enough.
